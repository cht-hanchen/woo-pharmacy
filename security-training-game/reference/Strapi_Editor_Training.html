01

What Strapi is

headless CMS

Strapi stores the content. hyte.com displays it.

Strapi is a headless CMS: it holds the text, images, products, blog posts and menus, and the website reads them through Strapi's API and renders the pages. You never change the design in Strapi. You fill in structured fields such as a title, an image or a button link, and the website decides how they look.

Languages (locales)

en-US · defaulten-GBjaesdefrplitnlkozh-Hant-TWzh-Hans-CNpt

Each language is its own version

  • Each locale has its own Draft and Published status.
  • Each locale must be saved and published separately.
  • When a locale does not exist yet, Strapi lets you create it and fill in from another locale, then you translate.
  • The list view's Available in column shows which locales exist.

Fields without the globe icon are shared

  • Changing a shared field changes it for every language at once.
  • Wrong locale is the most common mistake. Check the dropdown before you type.
  • New entries are created in the locale that is selected.

More actions behind ⋯

Publish multiple localesPublish several languages at once.
UnpublishTake the entry off the website. The content stays as a draft.
Discard changesThrow away unpublished edits and go back to the live version.
Unpublish multiple localesTake several languages offline at once.
DeleteRemoves the entry for this locale or all locales. Read the prompt carefully.

09

Do's & don'ts

rules of the road

Do

  • Check the locale before editing.
  • Save often; Publish only when you are sure.
  • Fill in alt text for every image.
  • Use the Published tab to compare with what is live.
  • Keep JSON fields valid, for example ["news"].
  • Preview is not set up yet, so check the site after publishing.
  • Ask in the team channel when you are unsure which field controls what.

Don't

  • Delete entries or media you did not create.
  • Change sku, categoryID, url or postUrl on existing entries without the web team. They drive links and the store.
  • Edit Settings, Preorder Settings, HS Code or Sitemap Settings.
  • Edit legal pages (Terms, Privacy, Cookie) before the content is approved.
  • Share your login, or paste API tokens into docs or chat.
